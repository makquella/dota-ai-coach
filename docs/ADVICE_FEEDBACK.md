# Оценка советов после матча (0.53.56)

Аудит (раздел D): `advice_follow.py` видит только смерть после срочного совета — это косвенный сигнал. Чтобы отличить неуместный или повторяющийся совет от верного, но проигнорированного, игрок после матча может отметить несколько карточек «Подсказки во время матча»: «Полезно», «Не к месту», «Повторялось». Во время игры оверлей ничего не спрашивает.

- Ключ карточки — `<t>:<dp>` (секунда матча и decision point), `advice_feedback.advice_key`. Бэкенд добавляет к каждой карточке разбора `key` и текущую отметку `feedback`, к деталям — `advice_feedback`.
- `POST /player/matches/{id}/advice-feedback {key, verdict}`; `verdict: null` снимает отметку. Неверный ключ или вердикт — 400, неизвестный матч — 404.
- Хранится в meta `advice_feedback:<account>:<match>` (JSON-объект, не больше 200 отметок на матч), уходит в резервную копию истории и возвращается при восстановлении (проверка формы через `META_JSON`). Никуда не отправляется.
- `GET /player/advice-feedback` и `/diagnostics` `player.advice_feedback`: счётчики по decision point, без текста советов. Облачная агрегация — только в будущем, отдельным opt-in с allowlist и правкой политики конфиденциальности.

Тесты: `backend/tests/test_advice_feedback.py` (настоящий матч из GSI, смена и снятие отметки, ошибки, сводка без текста, перенос через резервную копию, повреждённые данные).
