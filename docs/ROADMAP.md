# План розвитку після аудиту

Актуальна база в main: **0.53.3**, 64 герої з повним радником. Аудит від 7 жовтня 2026 досліджував `dd5a83c` (0.52.0); PR #97, #99 і #100–#103 уже злито. Зміни аудиту виходять як **0.53.1, 0.53.2 і далі**; нова minor-версія не потрібна для кожного виправлення.

Критерії, що перевіряються, і додаткові задачі вихідного аудиту: [AUDIT_ACCEPTANCE.md](AUDIT_ACCEPTANCE.md). Це поточний backlog. Старий продуктовий план збережено в [архіві](archive/roadmap-before-2026-10-07.md), подробиці хмарного зберігання — у [DATA_PLAN.md](DATA_PLAN.md). Підтверджених P0 в аудиті немає; security hardening і підтверджені збої даних залишаються обов'язковими незалежно від оцінки трудовитрат.

Прогрес за 17 основними зауваженнями F01–F17: **16 пунктів із підготовленими виправленнями й перевірками (близько 94%)**, F10 виконано частково. F13 закриває вихідні початкові extraction/UI критерії в 0.53.40. F12 закриває вихідний перший набір domain types і важливих I/O-контрактів у 0.53.39. F04 закриває вихідний критерій перших трьох типів findings у 0.53.38; це не означає перевірки довільних AI-тверджень. Це рахунок пунктів, а не трудовитрат: решта меж потребують окремих slices. У main злито чотири пункти (F05/F07/F08/F09, близько 24%); решта виправлень перебуває в послідовних відкритих PR. Продуктові пропозиції й додаткова automation з аудиту враховуються окремо нижче.

Після finish/queue recovery: backup/auth як окремі виправлення з fault tests. Не чекати на великий рефакторинг для підтверджених втрат даних. Для поведінки live-політики використовувати sanitized role recordings і fixed-clock replay, для нових UI-меж — справжні DOM-сценарії.

Наступні продуктові покращення після safeguards: джерела/покриття даних у розборі, preview відновлення історії, rotating local backups, порівнюваність Progress між версіями правил. Метрики й строки перевіряти на фактичних даних; їхня наявність у плані не означає, що функції вже реалізовано.

Мінімальний local D1 harness для transfer створено в `services/api/test/integration/`; інші SQL paths потребують розширення перевірок. Developer runner `scripts/dev.py`, version gate й optional scoped hook adapter підготовлено в 0.53.42 — [DEV_RUNNER.md](DEV_RUNNER.md). Вони використовують явні cwd/argv, враховують staged/unstaged/untracked paths; hooks залишаються вимкненими. Actual UK/EN Electron regression smoke вже виконується локально й у Windows CI; подальші сценарії додаються до нього.
