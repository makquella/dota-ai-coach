# План хранения данных (бесплатно)

Как приложение будет отправлять и где будет хранить:
- отчёты о проблемах;
- статистику использования (только по согласию);
- записи матчей для настройки советов;
- общий кэш данных OpenDota;
- ссылки «Поделиться разбором».

Всё должно укладываться в бесплатные тарифы. Лимиты указаны по документации
Cloudflare на август 2026 года; перед запуском их стоит перепроверить.

## Как сейчас

| Данные | Где | Проблема |
|---|---|---|
| История матчей, разборы, ключи | SQLite на компьютере игрока (`PLAYER_DATA_DIR`) | — (так и остаётся) |
| Разбор реплеев | OpenDota, бесплатно, по запросу приложения | Лимиты OpenDota; каждый игрок заново скачивает одни и те же справочники |
| ИИ-разбор | Ключ игрока (Gemini, Groq, OpenRouter) | — (так и остаётся) |
| Отчёт о проблеме | Файл в «Загрузках», ключи вырезаны | Игрок должен сам переслать файл; большинство не пересылает |
| Ошибки и статистика | Нигде | Разработчик не знает, что ломается у людей |

## Принципы

1. **Локально по умолчанию.** История матчей и ключи никогда не уходят в облако.
2. **Только с согласия.**
   - Отчёт о проблеме уходит только по кнопке, и перед отправкой видно, что
     именно отправляется.
   - Статистика — отдельный переключатель, по умолчанию выключен.
   - Запись матча — отдельное согласие на каждую отправку.
3. **Без личных данных.**
   - Никаких ключей: общий `redact` уже работает в `problem-report.js` и
     `app/diagnostics.py`, и сервер вырезает их ещё раз.
   - Никаких ников. Steam ID — только хеш с солью установки.
   - Идентификатор установки случайный, игрок может сменить его или удалить
     свои данные.
4. **Срок хранения.** Отчёты — 180 дней, статистика — 90 дней, записи матчей —
   60 дней, ссылки на разбор — 90 дней. Удаляет ежедневная cron-задача.
5. **Выключатель без релиза.** Приложение раз в сутки читает `GET /v1/config`,
   и любую отправку можно отключить на сервере.
6. **Страница «Конфиденциальность»** на сайте — до включения любой облачной
   функции.

## Выбор: Cloudflare Workers + D1 + R2

Домен `luhovyimvp.dev` уже в Cloudflare, поэтому сервис встаёт на поддомен
`api.luhovyimvp.dev` без новых аккаунтов.

| Сервис | Бесплатно | Для чего |
|---|---|---|
| Workers | 100 000 запросов в сутки, 10 мс CPU на запрос | Приём, проверка, маршрутизация |
| D1 (SQLite) | 5 ГБ, 5 млн чтений и 100 000 записей строк в сутки | Метаданные отчётов, дневные счётчики статистики |
| R2 | 10 ГБ-месяц, 1 млн записей и 10 млн чтений в месяц, исходящий трафик бесплатный | Файлы отчётов, записи матчей, опубликованные разборы, кэш OpenDota |
| Cron Triggers | Входят в Workers | Удаление старого, обновление кэша |
| Telegram Bot API | Бесплатно | Уведомление разработчику о новом отчёте |

Почему не другие варианты:
- **GitHub Issues напрямую.** Отчёты стали бы публичными, а в них сведения о
  системе. Годится только как запасной путь: кнопка «Открыть issue» с номером
  отчёта без содержимого.
- **Sentry, бесплатный тариф.** Хорош для падений, но ограничен по числу
  событий и не хранит файлы-записи. Можно добавить позже только для падений.
- **Supabase, бесплатный тариф.** Меньше места, проект засыпает без активности.
- **Firebase, Google Sheets.** Сложнее с конфиденциальностью и лимитами.

## Архитектура

```
Лаунчер ──HTTPS──▶ api.luhovyimvp.dev (Worker)
  │  outbox на диске      ├─ POST /v1/report   → R2 reports/…gz + D1 reports
  │  (повтор при сбое)    ├─ POST /v1/stats    → D1 daily_stats (1 строка/устройство/день)
  │                       ├─ POST /v1/session  → R2 sessions/…gz  (по согласию)
  │                       ├─ POST /v1/share    → R2 shares/<id>.json → luhovyimvp.dev/r/<id>
  │                       ├─ GET  /v1/meta/*   ← R2 кэш OpenDota (обновляет cron)
  │                       └─ GET  /v1/config   ← флаги включения
  └─ запасной путь: файл в «Загрузках» + «Открыть issue на GitHub»
```

Код — в репозитории, `services/api/` (проект wrangler, TypeScript). Деплой — GitHub
Actions с секретом `CLOUDFLARE_API_TOKEN`. Токен Telegram-бота и админ-токен
хранятся в секретах Worker и никогда не попадают в приложение.

### Защита от мусора

В приложении нельзя спрятать секрет, поэтому любой может слать запросы. Меры:
- **Схема и размер.**
  - Отчёт — до 2 МБ, статистика — до 4 КБ, запись матча — до 20 МБ (gzip).
  - Неизвестные поля отбрасываются.
- **Частота.**
  - Счётчик в D1 по хешу IP и идентификатору установки.
  - Лимиты: 5 отчётов и 1 запись матча в час с одной установки; 1 отправка
    статистики в сутки.
- **Контроль.** Выключатель `/v1/config`, быстрая очистка по префиксу в R2,
  суточная сводка объёма в Telegram.

### Расчёт на 1000 активных игроков в день

| Поток | Запросов в сутки | Записей D1 в сутки | Место |
|---|---|---|---|
| Статистика (одна свёрнутая строка в сутки) | 1 000 | 1 000 | ~1 МБ/мес в D1 |
| Отчёты (~20 в день × 200 КБ) | 20 | 20 | ~120 МБ/мес в R2, 180 дней ≈ 0,7 ГБ |
| Записи матчей (~30 в день × 5 МБ) | 30 | 30 | 60 дней ≈ 9 ГБ — на границе, поэтому 60 дней и выборочно |
| Кэш OpenDota (лаунчер раз в сутки) | 1 000–3 000 | 0 | ~50 МБ |
| Опубликованные разборы (~50 в день × 30 КБ) | 50 + просмотры | 50 | ~140 МБ за 90 дней |

Итого около 5 000 запросов в сутки при лимите 100 000 и около 1 100 записей
строк при лимите 100 000. Узкое место — место под записи матчей: их нужно
собирать выборочно (сервер через `/v1/config` просит запись только у части
тестеров).

Главное правило для статистики: **не одно событие — одна строка**. Лаунчер сам
складывает события за день в счётчики, например:

```json
{"day": "2026-09-27", "version": "0.2.1", "advice_shown": {"LOW_HP": 3, "SAFE_FARMING": 5}}
```

и отправляет одну строку. Так даже 10 000 игроков дадут 10 000 записей в сутки
вместо миллионов.

## Что именно собираем

**Отчёт о проблеме** (по кнопке) — тот же файл, что сейчас:
- статус лаунчера;
- настройки без ключей;
- `GET /diagnostics`;
- хвост лога.

Сервер отвечает коротким номером (`R-7F3K`). Лаунчер показывает его, чтобы игрок
мог сослаться на него в Discord или в issue. Разработчику приходит сообщение в
Telegram: номер, версия, первая ошибка из `diagnostics.errors`.

**Статистика** (по согласию, раз в сутки):
- версия, ОС, язык;
- сколько матчей записано;
- советов показано по типам;
- включён ли голос и оверлей;
- состояния ИИ (off/ready/error с кодом);
- коды ошибок синхронизации OpenDota;
- был ли эксклюзивный полноэкранный режим.

Этого хватит, чтобы видеть, какие советы срабатывают и где люди застревают при
настройке.

**Запись матча** (по согласию на каждую отправку): сырые состояния GSI из
`LIVE_SESSION_RECORDER` — только своего героя, без чата. Нужна, чтобы прогнать
матч через `simulate_live_gsi.py --session` и настроить правила на настоящих
играх.

**Опубликованный разбор** (по кнопке «Поделиться»):
- уже отрисованный JSON разбора: оценка, разделы, выводы, сборка, график;
- без Steam ID, ников и ИИ-вопросов;
- страница `luhovyimvp.dev/r/<id>` рисует его теми же компонентами.

## Разбор реплеев и общий кэш

- Реплеи и дальше разбирает **OpenDota бесплатно**. Сами реплеи мы не храним.
  Свой разбор на сервере выходит за рамки бесплатных тарифов: 10 мс CPU у
  Worker, а файлы реплеев весят десятки мегабайт.
- **Общий кэш справочников OpenDota.** Cron в Worker раз в сутки забирает:
  - `/heroStats`, `/constants/items`;
  - для популярных героев — `itemTimings`, `itemPopularity` и `matchups`.

  Всё кладётся в R2. Лаунчер берёт справочники у нас, а к OpenDota обращается
  только за своими матчами. Так лимиты OpenDota у игроков расходуются меньше, а
  при медленной OpenDota (замеряли до 35 секунд) разборы всё равно полные.
  Указать источник на сайте и в приложении («данные OpenDota») и соблюдать их
  условия.

## Риски

- **Cloudflare в России.** В 2025 году российские провайдеры замедляли ресурсы
  за Cloudflare. Лаунчер держит очередь исходящих отчётов на диске и повторяет
  отправку с паузами; если отправить не удалось — сохраняет файл и предлагает
  запасной путь. До запуска проверить у тестеров из России. Если не работает,
  второй адрес приёма — Yandex Cloud Functions (бесплатный лимит) с тем же API.
- **Лимиты могут измениться.** Выключатель `/v1/config` и расчёт выше позволяют
  быстро сократить поток.
- **Персональные данные.** Страница конфиденциальности, удаление по
  идентификатору установки (`DELETE /v1/device/<id>`), без ников и Steam ID.

## Этапы

| Этап | Что | Объём |
|---|---|---|
| 1 | `services/api/`: Worker + D1 + R2, `POST /v1/report`, `GET /v1/config`, Telegram-уведомление, ежедневная очистка, деплой из GitHub Actions. Лаунчер: «Отправить разработчику» с предпросмотром, outbox, номер отчёта. Страница «Конфиденциальность» на сайте | 2–3 дня |
| 2 | Статистика по согласию: переключатель в «Настройках → Приложение», дневные счётчики, `POST /v1/stats`, простая сводка (D1 → Markdown в Telegram раз в неделю) | 2 дня |
| 3 | Общий кэш OpenDota в R2 + чтение в `player_service` с откатом на OpenDota | 1–2 дня |
| 4 | «Поделиться разбором»: `POST /v1/share`, страница `/r/<id>` на сайте | 2–3 дня |
| 5 | Запись матчей по согласию для тестеров + выборка через `/v1/config` | 1 день |

Затраты — 0 ₽/месяц при нагрузке из расчёта выше. Первым имеет смысл сделать
этап 1: он сразу даёт отчёты от игроков.
